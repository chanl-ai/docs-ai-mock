1. What Docs AI is

Docs AI is a workspace product. A team connects its documents and data through sources, organises them into knowledge bases, and lets AI assistants and agents query those knowledge bases through a REST API, an MCP server URL and an in-app chat. A tools layer lets the same assistants act on the team's systems (REST calls, code, connected apps) with secrets kept out of prompts.

The dashboard exists so that an admin can get data in, see that it indexed correctly, tune how it is retrieved, and hand a working connection to a person or an AI client. Everything below is in service of those four jobs.

3. Conventions used in this spec

  • Routes are under /w/{workspaceSlug}/.... The current app serves both /dashboard/... and /workspace/{id}/dashboard/...; this spec collapses them into one workspace-scoped tree and keeps /dashboard/... as a redirect to the last-used workspace.
  • API calls are written in a neutral REST shape: GET /v1/workspaces/{ws}/knowledge-bases. Responses are { data, meta }; lists paginate with ?page&pageSize&sort&q and return meta.total. Errors are { error: { code, message, details } }.
  • Components are named as shadcn/ui primitives (Sidebar, DataTable, Dialog, Sheet, Tabs, Command, Form, Card, Badge, Progress, Breadcrumb, Skeleton, Alert, DropdownMenu, Select, Switch, Slider, Textarea, Tooltip, Popover, AlertDialog, ScrollArea, Toggle, Calendar) or existing components in the client tree: components/common/data-table.tsx, data-table-page.tsx, ui/page-header.tsx, ui/loading-state.tsx, ui/confirmation-dialog.tsx, ui/error-dialog.tsx, ui/tag-input.tsx, ui/slug-input.tsx, ui/selectable-card.tsx, ui/date-range-picker.tsx, app-sidebar.tsx, workspace-switcher.tsx, search-command.tsx, chat.tsx, onboarding/wizard.tsx, import-actions/*, actions/details/*, api-settings/*, clients/*, integrations/*, team/*, secrets/*, executions/*, audit-logs/*.
  • Every list screen uses the shared DataTable with toolbar (search input, faceted filters, view options), pagination, row selection, row actions menu, and column header sorting. This is stated once here and referenced as "standard table" below.
  • Every screen has the four shared states in Appendix E unless the screen section says otherwise: loading (Skeleton in the region's shape), empty (icon, one sentence, one primary button), error (Alert with retry), permission denied (Alert, no retry, link to Team).
  • Destructive actions use AlertDialog with the object name typed back only when the dependency count is greater than zero. Otherwise a plain confirm.
  • Long jobs (ingest, sync, export, import, delete-all) return a taskId; the UI polls GET /v1/workspaces/{ws}/tasks/{taskId} every 2 s while the sheet or page is open, and toasts on completion if the user has navigated away.

8.2 Upload files

Newmember · admin
Route
Dialog over 8.1, 7.2 and 5.5; component FileDropzone (new, in components/files/, built on react-dropzone as upload-source-dialog already is)
Purpose
Upload many files at once with visible per-file progress and clear failures.
Layout
Dialog (640px): dropzone area (accepts PDF, DOCX, XLSX, PPTX, CSV, TXT, MD, HTML; 50 MB each; up to 100 files per batch), target folder Select, Tags TagInput applied to all, then a file list with per-row Progress, size, status icon and Remove. Footer: "Upload n files" and a total Progress. "Add to a source after upload" Checkbox with a source Select.
Actions
For each file: POST /v1/workspaces/{ws}/files/upload-url { name, size, mimeType, folderId } → direct PUT to storage with progress events → POST .../files/{id}/complete. Concurrency 3. Cancel per file. Retry per failed file. When the Checkbox is on, the finished file ids are posted to POST .../sources/{id}/items { fileIds }.
States
Rejected on drop (type or size): row shows the reason, is not uploaded, and does not block the rest. Duplicate name in folder: row offers "Replace existing (new version)" or "Keep both (renamed)". Quota exceeded mid-batch: remaining rows fail with "Storage full"; uploaded ones stay. Dialog close during upload: AlertDialog "Uploads in progress will be cancelled".
Validation
MIME sniffed server-side; extension mismatch fails the row.

  5. Step 3: keeps Structure aware, 512/50, turns OCR on because some policies are scanned. Preview chunks looks right. Next.
  6. Step 4: adds exclude rule "Path glob: **/Archive/**" (count drops to 790). Maps metadata department ← column "Dept", locale = en. Adds tag "policy". Next.
  7. Step 5: Inherit from source (explained), schedule Daily 02:00, Subscribe to change notifications on, Deleted at source → Remove, Notify on failure on. Next.
  8. Step 6: reviews, leaves "Attach to knowledge base" pointing at the draft KB, clicks Create and sync now. The nested Sheet closes; the source is pre-selected in 6.2's Sources step.
  9. Step 3 of 6.2: picks Balanced. Create. POST .../knowledge-bases returns; the app navigates to 6.3.
  10. Overview shows Health: Indexing with "112 of 790 items". The source's sync run is visible under Recent index jobs. When it finishes, Health becomes Healthy (or Degraded with a failure count and a View failures link).

14.2 Add a file source and watch ingestion

  1. Member opens Files (8.1), clicks Upload. Drops 12 PDFs; two are rejected (one PPTX over 50 MB, one .zip) with reasons in the list; the other ten upload with per-row Progress. Ticks "Add to a source after upload", picks "Onboarding PDFs". Uploads finish; the Dialog reports 10 uploaded, 2 rejected.
  2. The files are posted to the source (POST .../sources/{id}/items { fileIds }) and processing starts. The Dialog offers "View source"; the member clicks it and lands on 7.3.
  3. 7.3 shows the Current run Card: "Processing 4 of 10 items, 0 failed", phases moving through parse, chunk, embed. Polling every 3 s.
  4. One item fails: the run ends Partial, the Errors Card shows "PDF is encrypted (1)". Member opens Items (7.4) filtered to Failed, sees the file, downloads the original, and later replaces it in Files (8.3 → Versions → Upload new version). The source reprocesses that item automatically; the item turns Indexed.
  5. Every KB reading the source shows the new documents in Documents (6.5) after its next index refresh, which the source completion triggers.

14.3 Tune retrieval in the playground

  1. Admin opens KB → Playground (6.7). Asks "What is the refund window for annual plans?".
  2. Answer arrives with two citations, but the Chunks tab shows the top hit is a 2019 policy. Admin opens the citation Popover and sees the document is Stale (older than 90 days).
  3. In the Settings rail, admin adds a metadata filter year in [2025, 2026] and raises the threshold to 0.6. Rail shows the Draft Badge. Asks again; the stale hit is gone and the answer cites the current policy.
  4. Admin sets Instructions to "Answer in one paragraph and always name the policy document", temperature 0. Asks again; the answer matches.
  5. Clicks Pin question to add it to the Test set with the rule "must cite refund-policy-2026.pdf". Runs the test set: all pinned questions pass.
  6. Clicks Save as KB defaults. 6.6 now shows the new values; the Request tab in the last result shows the exact body, and Copy as cURL takes the admin to 6.8 to hand it to a developer.

14.4 Connect an AI client

  1. Member opens Connect → AI clients (11.1) and clicks the Claude card. The Setup tab shows the workspace MCP URL in a config snippet.
  2. Auth method Select: chooses MCP token. Clicks Create token; the 11.2 Dialog opens with scopes knowledge:read and tools:run preselected, expiry 90d. Creates it; the token is injected into the snippet once and the Dialog asks for "I stored it".
  3. Member copies the snippet into the client's MCP settings and restarts the client.
  4. Verify tab: clicks Send test ping and waits; within a few seconds the Badge reads "Connected 2 s ago, claude-desktop/1.x". The card in the grid shows Connected.
  5. In the client, the member asks a question; the answer cites a document. In Docs AI, 9.2 Conversations shows the thread with Channel = MCP, and 6.9 counts the query under MCP callers.
  6. Alternative: member chooses Sign in with OAuth. The snippet has no token. The client opens 5.7; the member picks the workspace and clicks Allow. The client is registered under 11.3 by an admin beforehand.

14.5 Resolve a failed sync

  1. Home (5.8) shows "Needs attention: 1 source failed to sync". Admin clicks it and lands on 7.5 for the "Engineering wiki" Confluence source with the failed run's Sheet open.
  2. The summary reads: phase "list changes" failed, error class "permission", message "401 from Confluence: token expired". Counts show nothing changed. The Retry button is disabled because the failure is at the connection level, and the Sheet links to Integrations.
  3. Admin opens 11.5; the Confluence card shows Needs reauth. Clicks Reconnect; OAuth popup; success. The "What next" step is skipped since sources exist.
  4. Back on 7.3 the revoked banner is gone. Admin clicks Sync now. The run completes Partial: 3 items failed with "Attachment too large (60 MB)".
  5. Admin opens 7.6 Settings → Rules and metadata, adds exclude rule "Size under 50 MB is false" (or "MIME type is not application/zip"). Saves; the Dialog asks to reprocess; admin declines. Next sync is a full listing; the three items become Excluded, the run is Success.
  6. The KBs that read the source drop from Degraded to Healthy at their next refresh. The audit log (12.2) shows the reconnect, the rule change and both syncs.

Appendix E. Shared state rules

LoadingSkeleton in the shape of the region (table rows, stat cards, form fields). Never a full-page spinner inside the shell; the shell itself uses dashboard-skeleton.tsx only while the workspace resolves.
EmptyIcon, one sentence that says what the object is for, one primary Button, optional secondary link. Filtered-empty is different: "No results match" plus Clear filters.
ErrorAlert (destructive) with the server message and a Retry Button that re-runs the failed request. Form errors map from error.details[field] to the field. Streaming errors keep partial output.
Permission deniedAlert (neutral) "You do not have access to this page" with the required role and a link to Team. No Retry. Navigation items the role cannot use are hidden, not disabled.
Running jobProgress with "n of m" when the total is known, indeterminate otherwise, elapsed time, Cancel where supported. Poll 2 to 5 s while visible; toast on completion when navigated away.
DestructiveAlertDialog; the object name is typed back only when dependents exist; the dialog always lists what else is affected with counts.
Dirty formSticky Save footer appears only when dirty; leaving triggers an AlertDialog with Discard / Stay.
CopyEvery copyable value (URL, token, id, snippet) has a copy Button with a 2 s "Copied" state and a toast.
